SCHRITT 1: GITHUB / TEST-REPOSITORY
1) https://github.com/maertensjulino-design/website-TEST öffnen.
2) ZIP auf dem PC entpacken. NICHT die ZIP selbst ins Repo hochladen: alle Dateien und Ordner im entpackten Ordner gehören ins REPO-ROOT, sodass index.html direkt oben liegt.
3) Über Add file -> Upload files alle Dateien (gegebenenfalls in kleineren Gruppen) hochladen und committen. GitHub Browser-Upload großer/verzweigter Sites ist unhandlich; GitHub Desktop ist dafür zuverlässiger.
   Alternative: GitHub Desktop, Repo klonen, sämtliche extrahierten Dateien hineinkopieren, committen und pushen.
4) ACHTUNG: Das vorhandene Test-Repo ist PUBLIC: alle Quelldateien und Medien sind öffentlich zugänglich. Für Produktion ein PRIVATE Repo neu erstellen und dann admin/config.yml auf dieses Repo anpassen. Niemals Passwörter oder Tokens in Dateien ablegen.

SCHRITT 2: NETLIFY TESTSEITE
1) Bestehende Haupt-Domain juli-consulting.de NICHT verändern, bis die Testseite funktioniert.
2) Netlify > Add new project > Import an existing project > GitHub > website-TEST.
3) Production branch: main; Build command: LEER; Publish directory: . (Projektwurzel).
4) Veröffentlichen. Zuerst die automatisch zugewiesene *.netlify.app-Test-URL prüfen.
5) Unter /admin/ mit Sveltia CMS: 'Sign in with Token' wählen; bei GitHub ein begrenztes Fine-grained-PAT mit 'Contents: Read/Write' ausschließlich für das Test-Repo erstellen. Token nur im Editor eingeben; niemals in Dateien, E-Mails oder Chat kopieren.
6) Ein Feld 'Mitteilung' ändern, speichern und auf den nächsten Netlify-Deploy warten: dann sollte die Änderung online sichtbar werden.
7) Für komfortables OAuth-Login später GitHub OAuth App + Netlify OAuth Provider konfigurieren (kein Token nötig für den Kunden).

SCHRITT 3: PRODUKTIV
Erst nach Testen: Private Repo erstellen, Files hinüberkopieren, admin/config.yml anpassen und die bisherige Netlify-Website unter juli-consulting.de mit Git verbinden. Oder über den Netlify-Dashboard-Weg unter Project configuration > Developer settings > Continuous deployment > Repository > Push to new repository bei einer manuell veröffentlichten Site (nur wenn Netlify diese Option im Konto anzeigt).
Vorher aktuelle Netlify-Konfiguration, Formulare, Domain/DNS und bestehende Deploys sichern.
